Why Tau?

A full toolkit, not a fixed workflow

You should not have to choose between a capable coding agent and a configurable one. Tau gives you coding tools, delegation, web research, and resumable work — with controls for the models, prompts, tools, and integrations behind them.

Start with the defaults. Grow into specialist roles, reusable skills, named profiles, and your own extensions when the work calls for them. Your setup lives in files you can read, version, and change.

Follow Your first Tau task for installation, authentication, one bounded repository change, review, and resume. It explains Tau's trust and local-data boundary before the first model request.

More capability. More control.

Make the harness fit the way you work

Build a team, not a mega-prompt

Build task-specific agents and combine them into productive, integrated teams. Shape their roles and collaboration so you can direct the work at a higher level.

Take control of your workflow

Configure models, tools, instructions, and agent behavior—not just a handful of presets. Compose settings and profiles to make the harness work your way.

Keep the work, not just the answer

Resume sessions, explore transcript branches, and inspect what agents actually did through diffs, exports, traces, and usage estimates.

Make your setup compound

Turn a useful instruction into a skill, a workflow into a profile, and an integration into an extension. Reuse them across projects.

Agent rolesCompose a team with role-specific settings and behavior.Config

Tau defines agents through named roles that you compose into multi-agent teams. Give implementers, reviewers, and researchers different models, reasoning effort, communication styles, prompt fragments, and required skills.

Share defaults across a role group, then specialize each role. Tool policy belongs here too: select tools by name, group, or tag. Agents delegate to these configured roles, and you can select one directly with :role reviewer.

Role configuration →

harness.yaml · a coding team

agents:
  role_groups:
    coding:
      roles:
        implementer:
          description: Implement and test changes
          effort: 0.5
        reviewer:
          description: Independent correctness review
          effort: 0.9
          prompt_fragments:
            - name: review.focus
              text: Prioritize bugs over style.
Layered config & profilesOne base setup. Several ways to work.Config

Compose your setup from shared defaults, config fragments, and named profile overlays. Keep model selection, agent behavior, and extension configuration independently reusable instead of maintaining a separate config for every workflow.

Stack profiles at launch; later patches override earlier ones at the same scope. This example selects DeepSeek as the inherited model default and adds a reasoning adjustment. Explicit role-level model settings still win. Configure a provider named deepseek with the listed model first.

Profiles →

harness.yaml + shell

profiles:
  deepseek:
    agents:
      model: deepseek/deepseek-v4-flash
  focused:
    agents:
      effort: "increase:0.25"

# tau --profile deepseek
# tau --profile deepseek,focused

Project instructions & skill searchGrow your skill library, not every agent's prompt.Tools

Layer project and user AGENTS.md instructions while keeping a large skill library searchable on demand. Discovery reads bounded metadata, not every skill body. Agents search names and descriptions, optionally search content, then load an exact skill.

Project skills advertise their names and descriptions by default; user skills stay out of the prompt until searched. Set advertise: false for less frequently used project skills too. The library can grow without putting its whole catalog or contents into every agent's context.

Instructions and skills →

Example agent tool calls · your own skill library

# Search skill names and descriptions:
skill({"query": "rust review"})

# Load a skill by its exact name:
skill({"query": "rust-review-checklist"})

# Opt into searching skill contents:
skill({"query": "deadlock", "search_content": true})
Prompt templatesPut your working standards into the context.Config

Configure how agents communicate, reason about a task, and present their results. Named prompt fragments compose at the global, role-group, and individual-role levels, so shared preferences do not need to be copied into every role.

Use inline text for a short communication style, file-backed fragments for longer instructions, and Handlebars templates for context-dependent behavior.

Prompt controls →

harness.yaml · communication style

agents:
  prompt_fragments:
    - name: communication.style
      text: |
        Lead with the result or blocker.
        Be concise, direct, and technical.
        Explain tradeoffs, not basic concepts.
        Skip praise and routine progress updates.
Multi-agent delegationSplit the work without juggling separate chat windows.Workflow

Tau provides a rich multi-agent interaction toolkit: role-based delegation, asynchronous messages within and across sessions, progress watches, completion notifications, and waits. Configure the team through roles and its collaboration patterns through prompts and skills.

Coordination is optimized around push notifications. Separate agent contexts keep delegated work focused; background tools let independent work proceed while a command runs. Per-agent workdirs and cooperative directory locks coordinate shared files.

Agent coordination →

.agents/skills/team-review/SKILL.md · example skill

---
name: team-review
description: Coordinate parallel code reviews
---

Freeze the candidate before review.
Start two reviewer agents with that candidate:
- One checks correctness and failure paths.
- One checks test coverage and missing cases.
Run tests while they inspect the same version.
Use messages to answer their questions.
Wait for completion notifications; do not poll.
Consolidate findings before changing the code.
Ask the same reviewers to check the fixes.
Persistent sessionsDetach, resume, or connect from multiple terminals.CLI / UI

Sessions live in the harness daemon, independently of any one terminal UI. Detach while agents keep working, connect multiple UI instances to the same live session, or resume a stored session after its daemon stops.

Run tau serve under systemd or another supervisor for a headless, long-lived session you can attach to as needed. Interactive sessions shut down on the last ordinary UI quit unless you have used :detach; supervised sessions stay alive across UI disconnects.

Session lifecycle →

Shell · replace SESSION with its ID

# In Tau's UI, leave the session running:
# :detach

# Connect from one or more terminals:
tau attach SESSION

# After its daemon has stopped:
tau resume SESSION

# Or run headlessly under a supervisor:
tau serve --session SESSION --create-or-existing
Terminal UISpace-efficient, information-dense, and built for terminal workflows.UI config

Make the most of your terminal space with two major display modes: compact for daily use, and verbose for a richer, configurable view of agent activity and performance. Toggle between them with Ctrl+V. Verbose mode exposes extra detail—including reasoning summaries, tool activity, and turn statistics—to help you understand how your agents work.

Prompt history, completion, local ! shell commands, and external-editor prompts keep everyday interactions convenient. Customize key bindings, themes, mouse behavior, and display detail independently of your agent configuration.

Compaction controlsChoose when and how agents compact their context.Config

Control compaction through named, composable policies with model-aware thresholds, reserved headroom, lifecycle triggers, and agent-status conditions. Compact after an agent finishes a task, before its next inference, manually, or through an agent tool; configure policies globally or specialize them per role.

Tau supports provider-native compaction and its own configurable summary fallback, with custom mechanisms implemented through provider extensions. Provider-inline compaction and overflow recovery have separate controls from standalone policies. This example adds a status-aware policy while retaining the default before-inference safeguard; the model route determines the available mechanisms.

Context controls →

harness.yaml · compact at task boundaries

agents:
  compactions:
    after-task:
      reserve: 40000
      when:
        at: outer_turn_finished
        statuses: [done]
Debugging & observabilityInspect agent behavior, configuration, and performance.CLI

Inspect resolved prompts and tool definitions, durable event journals, agent-message timelines, and saved tool artifacts. Trace a delegated workflow across its agents, export conversations, or examine provider request and response captures when diagnosing a model issue.

Performance traces expose token and cache usage, cost estimates, tool and wait lifecycles, and compaction activity. Use compact human-readable output or machine-readable exports for your own analysis. Debug captures are best-effort and private; inspect them before sharing.

Traces & performance exports →

Shell · substitute your IDs

# Inspect the configured agent's inputs:
tau dev print-prompt
tau dev print-tools

# Trace a whole delegated workflow:
tau agent trace AGENT_ID --include-descendants

# Export performance data for analysis:
tau agent trace AGENT_ID --include-descendants \
  --format agent-performance-jsonl

# Inspect session activity and usage:
tau session stats --session SESSION_ID
Replaceable process extensionsYour tools, your language, your deployment.Config

Enable, replace, or wrap capabilities as ordinary supervised executables. Extensions can register tools and actions, subscribe to events, and receive declared secrets. Use your preferred language and configure process wrappers where needed.

Local scripting & optional integrationsGo beyond the repository when you need to.Opt-in

Enable bundled Rhai scripting for trusted event hooks and custom tools. Separately installed projects connect Tau to Slack, Telegram, Zulip, XMPP, email and calendars, Swarm coordination, and Rostra.

These are opt-in, not services activated by a default install. Each integration needs its own setup, credentials, and authority choices. The Rhai example enables execution of a trusted local script.

Extensions

Built in, maintained separately, or supplied by the community

Tau runs most capabilities as process extensions. Standard extensions ship in the Tau repository. External Tau projects are maintained in separate repositories but remain part of the Tau project.

Standard extensions

Provider backends

Built-in model providers and provider profile management.

Shell and filesystem

Shell commands, file operations, locking, and image inspection.

Utilities

One-shot, recurring, and daily reminders within a live session, plus opt-in papercut reporting.

Web search

Web search and URL fetching with configurable backend pools and credentials. Choose external services such as Exa and Parallel alongside provider-hosted search on compatible model routes.

Notifications

Configurable completion and idle hooks for terminal bells, OSC signals, and detached commands for desktop notification glue. Hooks ship unconfigured so you choose the interruptions.

Rhai

Opt-in trusted local scripting.

External Tau projects

Third-party extensions

tau-ext-searxng-search

Maintained by akohlsmith, this standalone SearXNG search tool supports configurable engines and categories, with optional local-category prioritization. See the project for installation and configuration.

Third-party extensions are independently maintained. A listing is not a compatibility, security, or maintenance endorsement; review the project before granting it access to Tau.

For external Tau projects, for example: nix profile install github:dpc/tau#tau-ext-slack. Installing a package does not enable it, create an account, add credentials, or authorize routes and tools. Then configure the service identity, Tau-managed secrets, allowed senders, routes, and role tool policy. See the extension guide.

Built to be taken apart

Unix foundations. Practical freedom.

Tau's process architecture makes its capabilities replaceable. The terminal UI connects to the harness over a local socket; providers and tool extensions communicate with it over stdio. Configure wrappers for remote execution or sandboxing where your environment needs them.

Your tools, working together

Open source. Inspectable. Yours to configure.

  • Native core. The CLI, harness, and bundled extensions ship in one native binary. Custom extensions can use their own languages and runtimes.
  • Composability. Start, stop, restart, redirect, and compose components with standard Unix tools.
  • Explicit boundaries. Local coding tools and configured extensions are powerful, trusted code. Choose external sandboxing when needed; a prompt is not an enforced write barrier.
  • No sealed box. Inspect the source, version your setup, and replace components instead of waiting for a single prescribed workflow.

Status

Bleeding-edge features. Fast-paced development.

Tau moves quickly, with a small but dedicated community building and refining powerful agent workflows. Expect new capabilities, rapid iteration, and occasional rough edges or configuration changes.

Who Tau is for

Tau is most useful for power users, especially developers, who want a powerful, deeply customizable tool rather than a fixed workflow. Configure your own agent teams, choose models and tools, and adapt the harness to the way you work.

Its Unix-centered architecture favors composability: ordinary processes, explicit interfaces, and components you can script, supervise, and replace. If you want your coding agents to work with your existing tools rather than dictate the rest of your setup, Tau is built for that.
