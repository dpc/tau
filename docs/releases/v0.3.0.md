# Tau v0.3.0

Released November 3, 2026.

User-facing changes since v0.2.1.

## Before upgrading

- **Update protocol-10 extensions with the harness.** The protocol advances from
  **10.2 to 16.2**; old protocol-10 extensions are incompatible. Existing
  **SDK 0.16.0 / protocol-16.0** extensions remain admitted with same-major
  minor-skew warnings and best-effort compatibility. Optional 16.1/16.2 metadata
  does not require them to rebuild. **Proto/client SDK 0.18.0 is published.**
  Rust source compatibility and wire admission are separate.
- **Migrate main-agent configuration.** Remove `agents.default_role` and
  `inter_session.receiver`, including profile overrides; Tau rejects these keys
  even when null or empty. Set role-only `main_priority`: the lowest nonnegative
  priority wins; zero is valid, and a winning tie is an error. Tau creates the
  optional main lazily and preserves its identity across restart. Changed
  priorities do not replace it; an unavailable winner has no fallback. Explicit
  `--role` starts ordinary work. Older mainless sessions remain valid.
- **Remote worker messages default to main review.**
  `inter_session.review_direct_messages` defaults to true. Main accepts
  authenticated remote-worker messages for review; the ACK **does not confirm
  worker delivery**. Only main can release the retained immutable message through
  `message_release`. Mainless sessions reject this input. Set the option to false
  for direct delivery. Local exact messages, human CLI messages, and
  external-adapter permissions retain separate paths. Release guarantees neither
  distributed exactly-once delivery nor inference or a reply.
- **Back up state before new writes.** New readers accept older history, but old
  binaries cannot decode new image-reference, partial-answer, main-agent, and
  other records. Intermediate validators may reject new compaction recovery
  histories. Unchanged journal framing does not make downgrades safe. Back up the
  complete Artifact store and transcript-root registry alongside journals;
  journals alone cannot preserve referenced images. Keep an old fallback and its
  pre-upgrade state separate.
- **Name the shell instance.** Use `!instance command` or `!!instance command`,
  even with one executor. That extension owns execution and path completion;
  completion has no terminal-host filesystem fallback. Single bang appends output
  without inference; double bang does not append it. Neither reruns commands
  after uncertain outcomes.
- **Final compaction failure pauses the matching model and branch.** New input,
  timers, ordinary terminals, and restart do not start another recovery episode.
  Recover through explicit `:compact` or authorized `agent_compact`. Manual
  failure and cancellation use the same stop policy. Configuration and credential
  changes still require a full harness restart; publication does not replace or
  restart running processes.

## Discovery and role readiness

Tau delivers skills and AGENTS.md guidance as marked user-context messages when
inference is ready, reusing exact versions retained across workdir changes,
branches, restart, and compaction. Preview discovery without inference through
`tau dev print-skills --workdir …` and `tau dev print-agents-md --workdir …`.
Skill previews default to discovery envelopes; Markdown/JSON formats retain the
full inventory. Startup summaries show original discovered paths.

Roles can declare `required_tools` to prevent startup, resume, or creation when
effective policy, model, or provider routes lack required registered tools. This
checks prerequisites, not running-agent health.

## Artifacts, images, and clipboard

Native clipboard paste accepts PNG, text, copied-file bundles, and opaque MIME
originals across compatible terminal/multiplexer hops, including SSH. Tau uploads
originals to shared artifacts and leaves references editable without submitting
the prompt. Grouped files enter the draft after all uploads finish. Cancellation
preserves the draft, though finalized immutable objects may remain.

Use `:export-to-clipboard KEY` with key-prefix completion to retrieve originals.
`--raw`, `--mime`, and `--file --name …` control the format. Each terminal/mux hop
needs support and permission; no OSC52 or remote-shell fallback exists. A file ACK
confirms a copied-file offer, not a paste into another application. Staged files
expire after one hour. Unconfirmed handoff keeps Tau interactive with the draft
preserved; `:quit-force` gives up the clean-input guarantee.

Artifact import/export preserves per-use filename and MIME hints; keys alone
cannot recover them. Import uses sanitized private temporary names. Both tools
are available under default Codex policy without ordinary shell-read access.

Eligible persistent `read_image` calls retain exact prepared images as verified
Artifact references. Ephemeral, memory-only, and unprepared calls stay inline.
Text-only routes omit images without downloading; missing or corrupt images fail
the affected request, not the provider. Generic observers receive neither image
bytes nor fetchable prepared-image keys.

## Providers and compaction

The separate **`chatgpt-plan`** provider adds public Sign in with ChatGPT and
Responses/SSE inference without importing legacy Codex credentials or falling
back to API-key billing. Setup must persist credentials (`--output -` is rejected).
It supports text, reasoning, Function tools, and local-summary compaction, but
not images, hosted tools, WebSocket continuation, or native compaction. Source
and loopback tests do not establish live account entitlement.

The private ChatGPT/Codex catalog adds **GPT-6.1 Terra** without changing defaults.
**`gpt-6.2-astra` is provisional**: its 272,000-token local budget is not verified
capacity; unverified capabilities and prices remain unadvertised. Audited
multimodal routes expose image reading. Unknown models stay conservative, and
local budgets do not guarantee backend capacity.

Codex displays partial answers without treating them as final summaries and
continues completed responses with `end_turn=false` in the same outer turn.
No-tool continuation allows at most 16 additional samplings. Failed/incomplete
responses retain available IDs and usage.

Retries honor validated Retry-After advice; recognized policy and model-not-found
errors terminate. `application_idle_timeout_secs` retains its 300-second default
per ChatGPT provider profile; Ping/Pong does not extend this inference deadline.

Standalone compaction retries pre-output transport failures in five-attempt
bursts, backing off one, two, four, then at most five minutes between bursts;
trusted longer delays still apply. Cancellation and `:retry` remain available.
Restart requires explicit recovery. Clean unusable local summaries can retreat
through bounded smaller prefixes. Invalid output, permanent errors, and failures
after semantic progress retain conservative handling. The opt-in
`when.at: outer_turn_starting` policy compacts before a new outer turn, not during
tool continuations.

## CLI and long-lived sessions

`tau message [--wait-response] <recipient> [message]` accepts literal UTF-8 stdin
when the message argument is absent. Waiting prints one submitted final response,
creates no temporary sender, and does not cancel delivered work on disconnect.
Exact addresses accept optional `&` and `@` markers independently.

`tau session kill` attempts multiple exact IDs and fails if any fail. Markdown
tables reflow with pane width; message and watched prose use Markdown rendering.
Running watched agents remain visible after reporting Done.

Long-lived sessions reclaim written history-cache prefixes without deleting
journals. Provider answers and tool terminals survive transient
persistence-admission rejection in the live process without rerunning external
effects. This neither restores payloads lost by older processes nor strengthens
crash durability.

Offline diagnostics chart latency, throughput, quota/token usage, and context
from content-free durable traces. These measure observed workloads and wall time,
not unique context, pure decoder speed, or invoices.

## Distribution and qualification

Native packaging covers **nine executables from Tau and seven external projects**,
including the Telegram gateway. This release updates Slack to **0.5.0**.
AMD64 and ARM64 retain individual and `tau-full` DEB, RPM, and tar.gz packages;
`tau-full` DEB/RPM is an exact-dependency metapackage.

The immutable `v0.3.0` tag identifies
`3eae7dc621b3f2d2f953a182b85cde03c0037fbb`. All 32 new crate versions are published;
the registry-only SDK consumer tests and an isolated locked application install passed.
Both hosted native builds passed, and all 67 public assets matched their manifests,
checksums, and source identity. Later source changes, including prepared SDK 0.19.0,
are not part of this release.

Publication does not activate or restart installed processes. Static checks do not
verify package-manager installation/removal, service startup, or broad
distro/CPU/kernel compatibility. Native requirements remain a conventional glibc
loader, glibc 2.34 or newer, libgcc, CA certificates, and the documented Linux 5.12
mount-API minimum.
NixOS users should use Nix. Checksums are not signatures or independent
attestations; these notes make no bit-for-bit reproducibility claim.
